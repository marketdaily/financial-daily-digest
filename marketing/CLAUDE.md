# marketing/（社群發文與行銷素材）

根規範見 `../CLAUDE.md`。本目錄鐵則：

- **發文唯一路徑**：winrig cron `~/.marketdaily-fallback/social_post_runner.sh`（各窗口每日鎖，2026-07-17 重排）：08:00–08:59 台股晨報 reel（09:00 開盤前）、14:00–14:19 `daily_run.py` 品牌貼文（一天唯一一篇）、14:20–17:59 台股 reel 補發窗、20:30–21:29 美股晚報 reel（21:30 TW 美股開盤前）；絕不手動補發
- **日報短影音產線（2026-07-08 上線）**：winrig cron `video_brief_runner.sh`（早窗 07:20–07:39 TW 台股 reel+音頻、晚窗 20:00–20:59 美股 reel+音頻（美股 reel 2026-07-17 起）＋每日鎖）跑 `video_brief/run_daily.sh`：公版日報→`extract.py`（數字逐字回驗）→`render.py`（Playwright 錄 1080x1920 品牌動畫+程序配樂）→`make_post.py`（確定性驗證:數字回對/禁用詞/規格/非黑幀/非白幀→KV 上傳 `media.marketdaily.ai`→post json）。**內容鐵則：只上市場級重點＋事實性漲跌%，絕不上買賣價位/建議文字**（2026-06-02 明牌出包根因修正）；驗證不過=不產 post json=當天不發，生成失敗推 admin。**reel 該不該有的唯一事實源＝當日日報 archive（2026-07-11 起）**：生成端 `video_brief_runner.sh` 與發文端 `post_daily_reel.py` 都以 `docs/output/digest_當日.html` 存在與否判斷——存在＝該有 reel（缺貨才告警），不存在（週日/假日）＝兩端同步靜默；**不准任何一端另外寫自己的星期/假日表**（07-11 兩端規則岔開的假警報教訓）。週六照常出 reel＝週末盤點版（extract 標 `weekend`，template/caption 自動換「本週」字眼，語音快報週末不產）。`social_post_runner.sh` 另有 14:20–17:59 reel 補發窗（冪等＋每日鎖）：生成端遲到或當日修好，cron 自己補發，不需人工
- **發前必驗**：`python daily_run.py --dry` 看下一篇 id → 讀 `social_posts.json` 該 id 的 caption＋圖 → 逐字比對現行事實（價格/來源數/勝率/方案/市況）。任何一條對不上 → 停手問用戶（2026-05-26 出包教訓）
- **內容補產唯一路徑（2026-07-06 Delvin 親令全自動化；2026-07-08 升級多代理 Workflow）**：winrig cron `~/.marketdaily-fallback/marketing_agents_weekly.sh`（每週日 10:00–10:29 TW）跑 Marketing Agents 5-skill 鏈。主路徑=headless claude 用 Workflow 工具跑 `.claude/workflows/marketing-generate.js`（研究→6 創作代理平行→評分平行→定稿）與 `marketing-verify.js`（**每則草稿一個全新 context 獨立驗證者平行裁決**，逐字比對 pricing/track-record 事實＋中英一致性＋合規，缺席=fail-closed 駁回——「發前必逐字驗」由這步履行）→ `promote_ad_creatives.py` 重掃合規＋產圖卡入佇列 → deploy docs。舊單體 prompt 在 `~/.marketdaily-fallback/ma_*_prompt_legacy.md` 僅當 Workflow 工具不可用時 fallback；shell 端計數/格式驗證不變是最後防線。成功/失敗都推播 admin，絕不無聲。人工不再是閘門，但 Delvin 隨時可改 `ad_creative_drafts.json` 的 status 駁回還沒發出去的草稿
- **social_posts.json 欄位慣例（2026-07-09）**：`images`（list）= IG carousel 多圖貼文（2–10 張，僅 instagram，auto_post.py 走 CAROUSEL API）；`retired`（字串=原因）= 永久跳過不發。**清舊存貨一律標 retired 不硬刪**——promote_win_cards/promote_tldr 只用本檔 id 去重，硬刪會被 runner 殭屍回填
- **留言閘門漏斗（2026-07-11 上線，源自 @100xengineers 拆解，見 memory reference_100xengineers_playbook）**：轉換型貼文 caption 只寫「留言『早鳥』」不放連結；winrig cron `comment_funnel_runner.sh`（每 10 分鐘）跑 `comment_funnel.py`——掃近 14 天含關鍵字 CTA 的自家 IG 貼文留言，優先私訊訂閱連結（需 `instagram_manage_messages` advanced access，核准前自動退公開回覆），state 在 `social_out/comment_funnel_state.json`。**Fail-closed 雙保險**：token 缺 `instagram_manage_comments` 時 ①`promote_ad_creatives.py` 拒收閘門型草稿入佇列 ②bot 推 admin 告警（24h 防重）。關鍵字整檔期固定「早鳥」，改關鍵字=改 `comment_funnel.py::KEYWORDS`。回覆口徑鎖死「限時免費＋早鳥永久保留免費權」，禁止暗示未來收費。**⏸️ 2026-07-30 起這條轉換軌實質休眠（Delvin 拍板 dq-70ca9a8e37 選 B）**：`_funnel_ready()` 兩條件中 token scope 早已到手，卡在 `COMMENT_FUNNEL_ADVANCED` 未開（Meta App Review Advanced access 未送），所以閘門型草稿一律進不了佇列 → 已把該角度從 `.claude/workflows/marketing-generate.js` 的 ANGLES **註解掉**（ANGLES 7→6），不再每週白燒創作＋評分＋驗證三個代理。**復原要兩件都做**：`.env` 加 `COMMENT_FUNNEL_ADVANCED=1` ＋ 解開那行註解；只做一件等於永遠不會再產這型草稿。`_funnel_ready()` 本身不要動，它是最後防線
- **新聞hook型草稿（觸及軌）**：外部新聞事實數字是「零捏造數字」的唯一例外——必須帶 `source_url`，獨立驗證者逐字對來源，非近 14 天或對不上=駁回；我方產品數據（勝率/訂戶數）依然絕對禁止寫死
- **新聞快評自動線（2026-07-22 上線，Delvin 親令「新聞一出直接po」）**：winrig cron `news_reactive_runner.sh`（三窗口 09:00–10:30 / 15:00–16:30 / 21:40–23:00 TW，錯開 reel 與品牌貼文窗；≤3篇/天+篇距120分）跑 `marketing/news_reactive.py`——cnyes 即時掃(tw/us/wd_stock)+NewsAPI 補掃 → 事件分級×權值股名單計分 → Yahoo chart 確定性算個股 RSI14/MA20/50/量能(LLM 只准引用不准自產數字) → headless claude 產 caption → **確定性閘(禁詞+必含UTM網址+「caption每個數字必在FACTS內」回驗)** → 全新 context 獨立驗證者裁決 → 圖卡上 KV(media.marketdaily.ai,不 deploy docs) → 直發 IG/FB/Threads(不入 social_posts.json 品牌佇列,冪等靠 post_log)。閘門任一不過=不發+該則當日標 seen 不重試。手動救援:`python3 -m marketing.news_reactive run --force`;看候選:`scan`
- 數字必可驗證，不可捏造（placeholder 一律「—」）；行銷素材**只放贏的**（`win_card_data.py` 資料層）
- 方案只有 **Premium**，沒有「Pro」；不送 Premium（推薦/KOL 用現金/分潤/站內額度）
- **organic only**：不投 Meta 付費廣告；ads-meta skill 輸出一律 organic 模式
- 個股分析內容不得與付費連結（合規鐵則，見根 CLAUDE.md）
- **封面不可白底（2026-07-09 用戶指令）**：所有社群素材一律深色品牌底。IG Reels 必帶 `thumb_offset`（auto_post.py 已固定 3000ms，勿拿掉）；make_post.py 驗證含 0/3/15/33s 非黑非白幀閘
- **Reels 一律配最 trending 音樂（2026-07-10 用戶指令）**：`auto_post.py::post_instagram_reel` 自動查 IG Audio API `GET /ig_audio` 三層曲源（授權音樂 trending 榜 → 原創音訊 → Sound Collection `product=ADS`），掛 `audio_configuration` 並把影片內建配樂靜音；container/處理階段失敗 → fail-open 退回烘焙配樂重來（publish 只跑一次防重複發文），發文絕不因音樂缺席；曲庫首次解鎖自動推播 admin。**已全通（2026-07-10）**：帳號已切 Creator＋token 已加 `ads_management`＋container 掛音樂 dry-run 驗證 FINISHED。⚠️ 兩個實測坑：①API 回應把曲目放 `audio` 鍵、id 叫 `audio_id`（與官方文件寫的 `data`/`id` 不同），讀錯鍵會誤判「曲庫空」；②alert-worker 推播裸 urllib UA 會被 Cloudflare 1010 擋，要帶 User-Agent。曲庫狀態隨時看 `auto_post.py check`「IG 曲庫」行。FB/TikTok/YT 的 API 無掛曲庫能力，維持烘焙配樂；**絕不把版權音樂直接烘進影片檔上傳**。有旁白的 reel 必須傳 `trending_audio=False`，否則旁白會被 `video_volume=0` 靜音
